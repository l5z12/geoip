# Database operations

Requires Node.js 24 (at least 24.10.0) and pnpm 10.34.7. Run commands from the repository root. Database scripts load `.env` when present; variables already supplied by the environment take precedence.

- `pnpm run infra:ensure`: confirm/create the configured `GEOIP_DB` R2 bucket.
- `pnpm run db:update`: download official GeoLite2 Country, City and ASN archives, validate, then prepare an inactive D1 slot and archive the originals in R2. Run `pnpm run deploy` afterward to select it.
- `pnpm run db:local`: download, import into Wrangler's local D1, and archive into local R2.

Download requires `MAXMIND_ACCOUNT_ID` and `MAXMIND_LICENSE_KEY` with GeoLite2 download entitlement. Remote operations require `CLOUDFLARE_API_TOKEN` and `CLOUDFLARE_ACCOUNT_ID`; the token also needs **D1: Edit** alongside the Worker/R2/zone permissions in the root README. No S3 credentials are used. Put all four in GitHub's protected `production` environment. CI never downloads databases or receives secrets. Do not commit `.data`, credentials, or database archives.

The downloader uses official MaxMind HTTPS endpoints with Basic authentication; native fetch removes Authorization on cross-origin redirects. Each of three attempts has a 120-second timeout. Each compressed archive is capped at 256 MiB and its decompressed tar at 384 MiB. Only regular entries/directories are accepted; archive paths are never extracted to disk. The combined validated MMDB files may not exceed 512 MiB of stored data. The offline scripts process full buffers and convert MMDB leaves to indexed D1 intervals. The Worker fetches complete JSON records from D1 and never reads R2 during lookups. Metadata must identify the appropriate dual-stack GeoLite2 edition, be at most 30 days old, and not more than two days ahead. Public IPv4/IPv6 probes exercise record decoding without assuming geographic locations or ASN identities. Country and City permit absent records and omitted geolocation fields: [MaxMind does not guarantee geolocation for anycast IPs](https://support.maxmind.com/knowledge-base/articles/maxmind-geolocation-coverage), and [undefined/empty fields are omitted](https://dev.maxmind.com/geoip/docs/databases/city-and-country/city-binary/). No `traits.is_anycast` flag is required to accept missing fields. Returned records, `country`, and City `location` must be maps when present; a supplied country ISO code must be two uppercase letters, and supplied latitude/longitude must be finite and in range. `registered_country` is never substituted for geographic country. ASN probes still require a positive safe-integer ASN and non-empty organization. Decoder errors always fail validation.

Update logs report download attempts, HTTP status, sizes, extraction, metadata/build age, and fixed public probe results. Validation failures identify the field or failing probe. Logs never dump authorization headers, signed redirect URLs, response bodies, raw database records, or dependency error messages.

Schema version 2 manifests contain whole-file SHA-256 and `pageSha256` for every 256 KiB page, including the short final page, and are capped at 256 KiB. Version = SHA-256 of the concatenated lowercase country, city and ASN MMDB SHA-256 hex digests, in that fixed order. `updatedAt` is the newest MMDB build time, never fetch time. Publishing rechecks page and whole-file hashes, schema, metadata, freshness, version, and timestamps. Before any D1 write, it uploads the versioned original MMDBs and then their immutable manifest to R2. It converts the validated MMDBs into local SQLite and checks its size and probes. When the inactive D1 slot's tables match this schema's layout, it copies the slot's rows page by page into `.data/slot.sqlite` and imports only the rows that differ from the build, including any edited by hand. Otherwise it imports the whole build. API failures stop publishing rather than forcing a full import. A two-hour lease row in the slot keeps other publishers out from the first write until deploy. Remote verification compares row counts, whole-table checksums (block hashes and content-derived record ids), and probe records. If a patched slot does not match, it is imported in full. The slot is then marked ready, and the archive `manifest.json` pointer is uploaded last. A deployment receipt is saved only after both D1 validation and R2 publication succeed. Failed earlier uploads cannot advance the archive pointer or produce a deployable receipt. `pnpm run deploy` rechecks the prepared release, live binding, and lease before selecting the D1 slot, then releases the lease. Overlapping publishers are refused by the lease; production workflows also share a non-cancelling concurrency group.

Original LICENSE/COPYRIGHT entries, when present, are retained under `.data/licenses/GeoLite2-{Country,City,ASN}/`. They are not uploaded as public assets. Read and comply with the [GeoLite2 EULA](https://www.maxmind.com/en/geolite2/eula) and [MaxMind GeoLite documentation](https://dev.maxmind.com/geoip/geolite2-free-geolocation-data/) before downloading, distributing, or serving results. The download account's current agreement controls your use; local notices are not a substitute. Do not redistribute raw databases publicly.

Deployment on main ensures infrastructure, updates databases, then deploys the Worker. The daily 04:23 UTC workflow validates and stages the database release, then redeploys to switch the D1 binding; scheduled execution is disabled on fork repositories. The Worker's daily cron prunes superseded generations older than 29 days. Tests use synthetic archives and mocked HTTP; live authenticated downloads require operator credentials and are not part of CI.

D1 uses two reusable slots (`geoip-lookup-a` and `geoip-lookup-b`) with read replication enabled and an APAC primary location hint. The live slot is never imported into. Imports contain statements below 90 KB/500 rows and files up to 64 MiB; a ready marker is written only after count, checksum, and probe verification. Ranges are packed about 64 per `blocks` row because D1 bills each written row. Block boundaries and record ids derive from content, so a patch rewrites only rows near a change. `D1_MAX_ROWS` (default 1,500,000) stops publishing before an import that would write more rows. Increase `D1_SCHEMA_VERSION` when changing the SQL schema or conversion semantics. Patches diff against the slot's actual rows, so a conversion change only makes the next patches larger; a layout change makes the next update import each slot in full. `D1_MAX_BYTES` defaults to 500,000,000 bytes and may be raised only within the account's plan limit. See the root README for capacity, rollout, and archive recovery instructions.
